# AutoSpeed → SNPE INT8

Готовая модель для приложения:
`../app/assets/qnx/autospeed_heads3o_int8.dlc`, 5 720 336 байт,
SHA-256 `703932324d4f05510ed00ad7aece40bdb6f6c70f46ec6f15f382537f992f99dc`.

Исходный ONNX в этом каталоге — AutoSpeed FP32, нормализованный до opset 12
для старого runtime: batch=1, вход RGB 1024×512. Он включён целиком, без Git LFS,
поэтому для преобразования не нужны соседние репозитории. Происхождение и лицензия
описаны в [THIRD_PARTY.md](../THIRD_PARTY.md).

## Что меняется в графе

1. `fix_conv1d.py` удаляет промежуточные Squeeze/Unsqueeze вокруг представления
   Conv1D через Conv2D: SNPE 1.55 не проводил нужную информацию о rank-3 тензорах.
2. `fix_splits.py` устраняет Split перед Conv: делит веса предшествующей Conv
   для блоков C2f и q/k/v attention. Проблемный путь на DSP давал invalid input buffer.
3. `cut2.py` отрезает YOLO-декодер и оставляет шесть выходов: DFL
   `conv2d_51/59/67` (64 канала) и классы `conv2d_56/64/72` (4 канала).
   Декодер перенесён в C++ `native/src/decoder.cpp`.
4. `snpe-onnx-to-dlc` создаёт FP32 DLC с `cls_enc.json`.
5. `snpe-dlc-quantize` выполняет enhanced quantization на калибровочных кадрах,
   сохраняя диапазон логитов классов −8…8 через `--override_params`.

Раздельные выходы необходимы для отдельного масштаба INT8 логитов классов:
общий диапазон с DFL заметно ухудшал чувствительность. Добавление Clip-слоя не
решало проблему, поскольку свёртка оставалась квантована по прежнему диапазону.
Выходы SNPE имеют порядок NHWC; C++ декодер учитывает это.

## Повторная конвертация

Нужны Docker, отдельно полученный SNPE **1.55.0.2958** и репрезентативные
калибровочные изображения. SDK в контейнер передаётся read-only.

Подготовьте свои RGB-изображения PPM (P6) 1024×512. Для исходной камеры 1920×1080
сначала обрезаются верхние 120 строк, затем оставшиеся 1920×960 масштабируются
bilinear до 1024×512. Например, из собственного ролика:

```bash
mkdir -p .local/calibration
ffmpeg -i /path/to/your-recording.mp4 \
  -vf 'fps=1,crop=1920:960:0:120,scale=1024:512:flags=bilinear' \
  -frames:v 100 .local/calibration/frame-%04d.ppm
SNPE_ROOT=/path/to/snpe-1.55.0.2958 ./models/rebuild.sh .local/calibration
```

Используйте кадры с разнообразными объектами, освещением и дистанциями.
`make-calibration.py` проверяет размер и записывает float32 little-endian HWC,
RGB/255 и input list. Преобразования и новый DLC находятся в `models/build/`.
Исходный DLC в APK автоматически не заменяется. После проверки на DSP:

```bash
./scripts/update-payload.sh model
./build.sh
```

Для исходной модели использовались 100 кадров регистратора. Эти личные записи
не опубликованы. Поэтому повторная квантизация на ваших кадрах не обязана дать
тот же SHA-256 и ту же точность; **для сборки приложения точный готовый DLC уже
включён**. Тесты на синтетических кадрах проверяют только работоспособность
инструментов конвертации, не качество распознавания.

## Результаты исходных экспериментов

На тестовом F515 отдельный запуск сети давал около 31,6–33,6 инференса/с.
Это не FPS всей системы с захватом и препроцессингом: рабочий цикл ограничен 15 FPS.
Сравнение на 10 кадрах вне калибровки дало 32 из 38 FP32-детекций при пороге 0,5,
без дополнительных детекций; медианный IoU совпавших рамок около 0,96.
Набор маленький и не является общей оценкой безопасности или точности на дороге.
