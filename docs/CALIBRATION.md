# Снимок для калибровки

В версии 0.1.6 под кнопками запуска/остановки находится **«Сделать снимок для
калибровки»**. Она получает кадр реальной фронтальной камеры. Можно использовать
её при остановленном распознавании.

После получения появляется предпросмотр. Архив остаётся в приватном каталоге
приложения; последний снимок доступен после повторного открытия экрана.
Нажмите **«Сохранить в Загрузки»**, чтобы получить архив в `Download/F515AdasQnx`,
или **«Поделиться…»**, чтобы передать его выбранному приложению. На Android 8–9
используется системный выбор места «Сохранить ZIP…». Автоматической
отправки на сервер нет. Удаление данных приложения удалит неэкспортированные снимки.

## Состав ZIP

| Файл | Содержимое |
| --- | --- |
| `frame.png` | Полный кадр 1920×1080 без обрезки, масштабирования и нарисованных рамок; преобразование UYVY → RGB BT.601 limited, PNG без потерь |
| `frame.uyvy` | Исходные пиксели камеры; UYVY, 2 байта на пиксель, строки без padding |
| `input.ppm` | RGB 1024×512, полученный **из этого же кадра** штатным C++ препроцессором |
| `metadata.json` | Размеры, stride, вход камеры, crop, sequence/timestamp AIS, время запроса Android, параметры преобразования, хэши, версия приложения и payload |
| `README.txt` | Описание форматов |

Для геометрической калибровки используйте полный `frame.png`. `input.ppm` показывает,
что получает сеть после удаления верхних 120 строк и bilinear resize. Квантование
SNPE принимает float32 RGB/255; `models/make-calibration.py` умеет преобразовать
этот PPM. Сам снимок не меняет существующую калибровку и не переобучает модель.

AIS timestamp монотонный, это **не UTC**. `request_time_unix_ms` — время Android
перед получением снимка, а не обещание точной синхронизации часов QNX и Android.
`reference_calibration` содержит текущие опорные константы приложения, а не
измеренную по снимку новую калибровку.

## Как работает захват

`fcwd snapshot=<path> input=4` выполняет отдельную ветку до инициализации SNPE,
PPS и сетевого канала распознавания. Для неё приложение создаёт временную копию
бинарника под другим именем `/dev/shmem/fcwshot_<uuid>`. Захват не заменяет
исполняемый файл работающего `fcwd` и не запускает предупреждения.

Отдельный AIS-клиент получает один кадр. Пиксели сразу копируются в обычную память,
после чего camera buffer освобождается и клиент закрывается. Затем тот же
`Preprocess`, который используется в распознавании, готовит вход сети.

Android получает размер и SHA-256 от QNX. Сначала пробует прочитать файл через
точный NFS export, при ошибке использует base64 по telnet. Резервный поток
декодируется построчно в файл с ограничением размера. Требуются уникальные маркеры
начала/конца, точный размер и хэш. После чтения проверяется структура кадра.
Временные файлы QNX удаляются; ZIP публикуется локальным переименованием из `.part`.

Доступ к архиву для отправки даётся через read-only ContentProvider и временное
разрешение конкретного URI. Другие файлы приложения не предоставляются. Сохранение
на Android 10+ использует MediaStore Downloads и временный `IS_PENDING`, без
WRITE_EXTERNAL_STORAGE. На Android 8–9 используется Storage Access Framework.
На тестовой прошивке F515 системный picker возвращал на главный экран, поэтому
для Android 10+ сохранение не требует его запуска.

## Формат временного пакета

Внутренний формат `F515CAL1`: 64 байта заголовка little endian, затем UYVY и RGB.

| Смещение | Поле |
| --- | --- |
| 0 | 8 байт ASCII `F515CAL1` |
| 8, 12, 16 | uint32 width, height, packed stride |
| 20 | uint32 camera sequence |
| 24 | uint64 AIS timestamp ns |
| 32, 36 | uint32 camera input, crop top |
| 40, 44 | uint32 model width, height |
| 48, 52 | uint32 UYVY bytes, RGB bytes |
| 56, 60 | uint32 flags=1 (UYVY/BT.601 limited), reserved=0 |

Для штатного кадра пакет содержит 5 720 128 байт. Размеры ограничены до выделения
памяти; лишние, усечённые, неизвестные или повреждённые пакеты отклоняются.
