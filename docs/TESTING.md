# Проверка

## Проверки без ГУ

```bash
./tests/run-host-tests.sh
python3 scripts/qnx-assets.py
python3 scripts/check-public-tree.py
./build.sh
./tests/build.sh
```

Host-тесты используют временные файлы и синтетический TCP-сервер на loopback,
не подключаются к ADB реального ГУ. Проверяется 51 условие: 28 для компонентов
и метаданных обновления, 23 для ADB-транспорта. Включены порча при том же размере,
неполный комплект, некорректный URL/хэш/размер, последовательные shell-запросы,
устаревшие пакеты соединения, checksum, обрыв, таймаут, отмена, маркер окончания
между пакетами и ограничение буфера большого вывода.

`check-public-tree.py` проверяет staged-файлы либо файлы последнего коммита на
запрещённые имена и типовые секреты, включая бинарные данные. Выводит только имя
файла и тип находки, без содержимого. Это дополнительная проверка, не доказательство
отсутствия произвольного секрета в любом возможном формате.

`native/build.sh` дополнительно проверяет хэши внешних зависимостей, выполняет
компиляцию/линковку и сверяет все динамические импорты с реальными QNX-библиотеками.

## Проверки на ГУ

Обычный и инструментальный APK должны иметь одинаковую подпись. Устанавливайте
их через разрешённый прошивкой установщик. `tests/install-device.sh` только
переносит оба APK в Download; при нескольких устройствах задайте `ADB_SERIAL`.

```bash
./tests/build.sh
./tests/install-device.sh
# После ручной установки обоих APK:
adb shell am instrument -w -r \
  su.dsr.f515.qnx_adas.autostarttest/su.dsr.f515.qnx_adas.MaintenanceDeviceTest
```

Дополнительные параметры `am instrument` (перед именем компонента):

| Параметр | Действие |
| --- | --- |
| `-e repair true` | Пустая/повреждённая установка в отдельном тестовом каталоге QNX |
| `-e fallback true` | Принудительная передача полной модели через telnet |
| `-e cloud true` | Чтение облачного JSON |
| `-e install true` | Реальная установка доступного обновления; нужен совместимый сертификат |

Автозапуск проверяется отдельно:

```bash
adb shell am instrument -w -r \
  su.dsr.f515.qnx_adas.autostarttest/su.dsr.f515.qnx_adas.AutostartDeviceTest
```

Исходное состояние: автозапуск выключен, `fcwd` остановлен. Тест временно запускает
распознавание с выключенными звуком и баннером, проверяет кадры, один процесс при
повторных событиях, остановку и выключение автозапуска. В конце восстанавливает
настройки и останавливает запущенное им распознавание. Это вызовы обработчика
boot/update, **не фактическая перезагрузка ГУ**.

## Что проверялось для официальной 0.1.5

На тестовом ГУ выполнены: установка компонентов в пустой отдельный каталог,
повторная проверка, повреждённый бинарник того же размера, неверные права,
каталог вместо модели, файл вместо базового каталога, резервная telnet-передача
всей модели 5,7 МБ. Проверки автозапуска получали реальные кадры и не оставляли
дубликатов процесса. Проверен переход тестовой предыдущей версии на опубликованную
0.1.5 через облачный установщик.

При подготовке публичного комплекта отдельно пересобраны APK, инструментальный
APK и QNX ELF с локальными тестовыми ключами; host-тесты прошли. Официальные
подпись и проверенный payload не заменены результатами этих сборок. Сборки
с новой подписью в этот проход на рабочее ГУ не устанавливались.

Публичный набор также выгружен через `git archive` в отдельный каталог и собран
без исходных рабочих папок, с заново созданными ключами и явным импортом SDK/runtime.
Цепочка ONNX → FP32 DLC → INT8 DLC проверена на синтетических PPM-кадрах;
это проверка инструментов сборки модели, а не калибровка для эксплуатации.

## Измерения и ограничения

На стенде 23.10.2026 получено около 14–15 обработанных кадров/с: CPU-preprocess
23–27 мс, DSP около 36 мс, postprocess около 0,2 мс. Память `fcwd` около 20 МБ,
нагрузка около 4,3% суммарного QNX CPU (примерно 34% одного ядра). Условия,
прошивка и нагрузка могут изменить результат.

Раскладка скорости `VehicleGauges` и визуальное соответствие кода баннера приборки
требуют дополнительных проверок. Сопоставление с VHAL предусмотрено для диагностики.
Тесты восстановления и сборки не подтверждают правильность каждого предупреждения
в реальном движении. Новый native-бинарник/модель нужно проверять на целевой прошивке.
