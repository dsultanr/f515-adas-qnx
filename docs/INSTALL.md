# Установка, доступ и восстановление

## Официальная версия

Скачайте [0.1.5](https://tm.dsr.su/f515/adas-qnx/F515AdasQnx-0.1.5.apk), перенесите
APK в Download и установите через поддерживаемый прошивкой установщик, например
iSpace Toolbox. На тестовой прошивке прямой `adb install`/`pm install` ограничен.

Если уже стоит официальная **0.1.3**, установите 0.1.5 поверх неё. Удалять приложение
и очищать данные не нужно. Пакет и подпись официальных версий совместимы, настройки
звука, баннера и автозапуска сохраняются. В 0.1.3 ещё нет встроенного обновлятора.

После открытия нажмите «Проверить и выдать права», затем «Проверить и восстановить
компоненты QNX» или запустите распознавание. Приложение само устанавливает бинарник
и модель. Заранее копировать файлы из рабочего каталога разработчика не требуется.
Автозапуск включается отдельно и по умолчанию выключен.

«Пустое ГУ» здесь означает отсутствие предыдущих файлов ADAS. Всё ещё нужны
совместимая прошивка F515, работающие штатные AIS/SNPE/DSP, root-adbd на loopback
5555, разрешённый ADB-ключ и доступ из Android к QNX по внутренней сети.
APK не устанавливает прошивку, не получает root на неподготовленном устройстве
и не заменяет отсутствующие системные библиотеки.

## Сборка из исходников

В публичном репозитории нет ключей автора. `scripts/init-keys.sh` создаёт ваши.
Собственный сертификат несовместим с официальным APK. Для тестирования используйте
отдельное ГУ/профиль либо осознанно удалите официальное приложение после сохранения
нужных настроек. Инструментальные тесты тоже должны быть подписаны вашим ключом.

Чтобы приложение подключилось к root-adbd, авторизуйте публичную часть своего
ключа (`.local/keys/adbkey.pub`) обычным для вашей прошивки способом. При наличии
диалога RSA подтвердите именно ваш ключ. Если авторизация на прошивке выполняется
через список `/data/misc/adb/adb_keys`, добавляется только публичная строка с
сохранением существующих ключей и штатных прав/контекста файла. Получение исходного
root-доступа зависит от прошивки и не выполняется этим проектом.

Не заменяйте `~/.android/adbkey` компьютера ключом приложения без необходимости.
Ключи приложения и компьютера могут сосуществовать в списке доверенных ключей ГУ.

## Что восстанавливается

Перед запуском проверяются SHA-256 и размер обоих компонентов непосредственно
на QNX. Исправляются отсутствующие файлы, повреждение с тем же размером, права,
файл вместо каталога, каталог или ссылка вместо файла. Конфликтующие объекты
переименовываются в `.broken_<id>`, после чего комплект восстанавливается из APK.

NFS используется первым. Если запись не удалась или записаны нулевые/неверные
байты, включается резервная передача через telnet. Запуск допускается только
после повторной проверки. Перестановка APK и очистка Android-данных для этого
не нужны. Свободное место на постоянном разделе всё равно необходимо.

## Разрешения и обновления

Кнопка прав проверяет разрешение установки пакетов и исключение из оптимизации
батареи для своего пакета и текущего пользователя. Уже выданное разрешение не
перезаписывается: на тестовой прошивке это может завершить процесс. При первой
выдаче отдельная root-команда заканчивает настройку и возвращает экран приложения.
Если ADB недоступен, доступны системные страницы разрешений.

Проверка обновления запускается по кнопке. Проверяются HTTPS-адрес, размер,
SHA-256, пакет, версия и сертификат; установка идёт через PackageInstaller с
системным подтверждением. Работающий `fcwd` после обновления APK принудительно
не перезапускается. Новый комплект применяется при следующем запуске демона.
